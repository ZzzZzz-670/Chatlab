# 08_纠偏触发规则.md

## 一、文档定位

本文定义「对话实验室」日常对话 Agent 如何识别、处理和沉淀“纠偏”。

纠偏不是承认系统失败，也不是推翻全部画像，而是在新信息出现时，对已有判断进行更精细的调整。

它服务于：

- 孩子画像更新；
- 家长反馈处理；
- 首次诊断卡持续校准；
- 待观察点更新；
- 家庭互动模式修正；
- 沟通预演优化；
- 阶段性小观察；
- 系统长期可信度。

一句话：

> 纠偏的核心不是“之前错了”，而是“新信息让原来的判断需要更谨慎、更具体、更分场景”。

---

## 二、为什么需要纠偏机制

「对话实验室」不是一次性诊断工具，而是长期使用的孩子理解系统。

首次诊断卡一定是不完整的。家长第一次输入的信息有限，孩子状态也会变化，后续对话中会不断出现新事实。

如果系统不纠偏，会出现三个问题：

1. 旧判断压过新事实；
2. 系统一直重复不准确的话；
3. 家长会觉得系统只是套模板，而不是真的越来越懂孩子。

因此，日常 Agent 必须具备纠偏能力：

```text
看到新信息
↓
判断它是否挑战旧理解
↓
决定是降权、补充、拆分、缩小范围，还是替换
↓
前台自然说明
↓
后端写入纠偏记录
```

---

## 三、纠偏的基本定义

纠偏是指：

```text
当新信息、家长反馈、孩子问卷、近期成长记录或家庭互动变化，与既有判断存在差异时，系统对旧判断进行调整。
```

纠偏不一定意味着旧判断完全错误。

更常见的是：

- 旧判断适用范围太宽；
- 旧判断只适用于某些场景；
- 旧判断需要增加例外；
- 新信息补充了另一种可能；
- 家长反馈让置信度降低；
- 孩子状态已经变化；
- 家庭互动模式发生了细微变化。

---

## 四、纠偏和普通更新的区别

## 1. 普通更新

新信息没有挑战旧判断，只是在原判断基础上增加证据。

示例：

旧判断：

```text
孩子在被连续追问时容易沉默。
```

新信息：

```text
今天问他为什么不写，他又沉默了。
```

处理：

```text
增强旧画像权重。
```

---

## 2. 纠偏

新信息改变旧判断的适用范围、置信度或解释方向。

示例：

旧判断：

```text
孩子拿手机主要是逃避学习。
```

新信息：

```text
最近三次都是写完一段后拿手机，而且能按时回来。
```

处理：

```text
旧判断缩小适用范围：学习前拿手机可能是逃避；完成任务后拿手机更可能是恢复需求。
```

---

## 3. 完全替换

旧判断和新事实明显冲突，且旧判断缺少证据。

示例：

旧判断：

```text
孩子不愿意表达学校情况。
```

新信息：

```text
孩子其实每天会和妈妈聊学校，只是不愿意在爸爸面前说。
```

处理：

```text
旧判断拆分或替换为：孩子不是不愿意聊学校，而是表达对象和场景有差异。
```

---

# 五、纠偏触发条件

纠偏主要由以下 8 类情况触发：

```text
1. 家长明确否定
2. 家长点击“不太像”
3. 新事实和旧画像冲突
4. 多次近期记录改变旧趋势
5. 孩子问卷和家长观察不同
6. 旧诊断卡解释范围过宽
7. 家庭互动模式发生变化
8. 家长长期关注目标发生变化
```

---

# 六、触发条件一：家长明确否定

## 1. 常见输入

```text
不太像。
不是这样。
他不是怕休息不够。
他不是不会，他就是根本不想开始。
这个判断不准。
你说的这个和我家不太一样。
```

## 2. 处理原则

家长明确否定时，Agent 不解释、不辩解、不坚持旧判断。

先做三件事：

```text
1. 接受修正
2. 降低旧判断权重
3. 用一个关键问题重新定位
```

## 3. 前台表达

```text
明白，那我先把前面那个方向降一下权重。
```

```text
这个信息会让前面的判断更谨慎一点。
```

```text
我改一下前面的理解。这次可能不是____，更像是____。
```

## 4. 不要说

```text
但根据之前的信息……
您可能没有注意到……
系统判断仍然认为……
```

## 5. 写入候选

```json
{
  "correction_candidates": [
    {
      "old_judgment": "孩子拖延主要和休息边界有关",
      "new_judgment": "本次更偏学习启动困难",
      "reason": "家长明确否定休息边界解释",
      "correction_type": "deprecate_old",
      "confidence": 0.72
    }
  ]
}
```

---

# 七、触发条件二：家长点击“不太像”

## 1. 触发来源

前端按钮：

```text
有点像｜不太像｜补充一点
```

当家长点击“不太像”时，应进入轻纠偏流程。

## 2. 后端处理

按钮触发后，后端应传入：

```json
{
  "feedback_type": "reject",
  "target_judgment_id": "entry_001",
  "target_text": "孩子拿手机主要是逃避学习"
}
```

## 3. Agent 处理

Agent 不需要重新解释一大段，只需：

- 降低对应判断权重；
- 简短说明会调整；
- 邀请家长补充一个事实；
- 或给出一个分场景问题。

## 4. 前台表达

```text
收到，我先把这个判断降一下权重。那这件事更可能要换个角度看：他拿手机通常是在任务开始前，还是完成一段之后？
```

## 5. 写入

```json
{
  "correction_candidates": [
    {
      "old_judgment": "孩子拿手机主要是逃避学习",
      "new_judgment": "该判断被家长反馈为不太像，需重新确认手机出现时间和功能",
      "reason": "家长点击不太像",
      "correction_type": "deprecate_old",
      "confidence": 0.65
    }
  ],
  "pending_observation_candidates": [
    {
      "content": "重新确认孩子拿手机更常出现于学习前、学习中、完成后还是无任务时",
      "related_scene": "phone_rest"
    }
  ]
}
```

---

# 八、触发条件三：新事实和旧画像冲突

## 1. 定义

家长提供的新事实，与旧画像中的稳定判断不一致。

## 2. 示例

旧画像：

```text
孩子在被连续追问时容易沉默。
```

新事实：

```text
今天我问他为什么不写，他没有沉默，反而说“我不知道从哪开始”。
```

处理：

```text
不是删除旧画像，而是记录例外和成长变化。
```

## 3. 可能处理方式

| 新事实类型 | 处理 |
|---|---|
| 一次例外 | 写 growth_record + add_exception |
| 多次例外 | 降低旧判断权重 |
| 明显冲突 | 标记 conflicted |
| 解释更细 | split_judgment |
| 新事实更可靠 | narrow_scope 或 replace_old |

## 4. 前台表达

```text
这个变化挺值得记一下。以前一到这个话题他更容易沉默，这次能说出“我不知道从哪开始”，说明至少这次不是完全关闭，而是露出了一点具体困难。
```

## 5. 写入

```json
{
  "growth_record_candidates": [
    {
      "scene_type": "communication",
      "signal_type": "表达开放",
      "content": "孩子在作业场景中说出“不知道从哪开始”，与过去沉默不同",
      "direction": "positive",
      "importance": "high"
    }
  ],
  "correction_candidates": [
    {
      "old_judgment": "孩子在被问作业时容易沉默",
      "new_judgment": "孩子在部分低压力问法下可以说出具体困难",
      "correction_type": "add_exception",
      "confidence": 0.68
    }
  ]
}
```

---

# 九、触发条件四：多次近期记录改变旧趋势

## 1. 定义

单次新信息可能只是例外，但多次同向记录说明旧判断需要调整。

## 2. 示例

旧判断：

```text
孩子写作业拖延主要因为态度不自觉。
```

近期记录：

```text
连续三次都显示孩子不是不写，而是不知道先做哪一步。
```

处理：

```text
旧判断降权，新增“任务拆解困难 / 学习启动困难”。
```

## 3. 判断标准

可触发纠偏的情况：

```text
同类新事实出现 2 次以上：写候选纠偏；
同类新事实出现 3 次以上：增强新判断，降低旧判断；
同类新事实出现 3 次以上且家长确认：可替换或拆分旧判断。
```

## 4. 前台表达

```text
这几次放在一起看，我会把前面“不自觉”那个方向放轻一点。更明显的线索是：他不是完全不想做，而是经常卡在“从哪一步开始”。
```

## 5. 写入

```json
{
  "correction_candidates": [
    {
      "old_judgment": "孩子作业拖延主要是不自觉",
      "new_judgment": "孩子作业拖延更常表现为任务启动和拆解困难",
      "reason": "近期多次记录显示孩子卡在开始步骤",
      "correction_type": "replace_old",
      "confidence": 0.78
    }
  ]
}
```

---

# 十、触发条件五：孩子问卷和家长观察不同

## 1. 定义

孩子问卷中的自述和家长观察不一致。

## 2. 示例

家长观察：

```text
孩子就是不想学习。
```

孩子问卷：

```text
孩子说最难的是“不知道任务做到哪里算结束”。
```

处理：

```text
不判定谁对谁错，写待观察和纠偏候选。
```

## 3. 前台表达

```text
孩子问卷里有一个信息值得放进来：他提到自己更在意“做到哪里算结束”。这不一定推翻您说的拖延，但会让原因更具体一些，不只是简单不想学。
```

## 4. 写入

```json
{
  "correction_candidates": [
    {
      "old_judgment": "孩子拖延主要是不想学",
      "new_judgment": "孩子拖延可能与任务边界不清有关",
      "reason": "孩子问卷提到不知道做到哪里算结束",
      "correction_type": "narrow_scope",
      "confidence": 0.7
    }
  ],
  "pending_observation_candidates": [
    {
      "content": "继续观察任务边界清楚时，孩子作业启动是否更容易",
      "related_scene": "task_start"
    }
  ]
}
```

# 十一、触发条件六：旧诊断卡解释范围过宽

## 1. 定义

首次诊断卡中的判断太大、太概括，需要日常对话拆细。

## 2. 常见旧判断

```text
孩子有逃避倾向。
孩子对学习抵触。
孩子压力较大。
孩子亲子沟通关闭。
孩子手机使用承担逃避功能。
```

这些判断不能长期原样使用，需要在日常对话中分场景校准。

## 3. 拆细方式

示例：旧判断“孩子手机使用是逃避”。

可拆成：

```text
学习前拿手机：可能是逃避压力。
写到一半拿手机：可能是卡点或疲惫。
完成一段后拿手机：可能是恢复需求。
睡前拿手机：可能是情绪缓冲和睡眠节律。
无任务时停不下：可能是即时反馈依赖。
```

## 4. 前台表达

```text
我把前面对手机的理解拆细一点。不是所有拿手机都等于逃避，要看它出现在什么时候。
```

## 5. 写入

```json
{
  "correction_candidates": [
    {
      "old_judgment": "孩子手机使用主要是逃避学习",
      "new_judgment": "孩子手机使用需要按出现时间拆分为学习前逃避、完成后恢复和睡前情绪缓冲等不同场景",
      "correction_type": "split_judgment",
      "confidence": 0.76
    }
  ]
}
```

---

# 十二、触发条件七：家庭互动模式发生变化

## 1. 定义

旧的家庭互动循环不再完全适用，或出现了新的有效互动经验。

## 2. 示例

旧模式：

```text
追问—沉默循环。
```

新事实：

```text
家长这次没有问“为什么”，只问“卡在哪一步”，孩子愿意说。
```

处理：

```text
保留旧模式，但新增有效互动经验。
```

## 3. 前台表达

```text
这个经验值得存一下。以前一问“为什么”，孩子容易沉默；这次您换成“卡在哪一步”，他反而能说出来一点。后面类似作业场景，可以先从具体卡点问起。
```

## 4. 写入

```json
{
  "correction_candidates": [
    {
      "old_judgment": "作业场景中容易出现追问—沉默循环",
      "new_judgment": "当家长减少原因追问、改问具体卡点时，孩子更愿意表达",
      "correction_type": "add_exception",
      "confidence": 0.75
    }
  ],
  "family_interaction_candidates": [
    {
      "pattern_name": "低追问下表达增加",
      "content": "家长减少连续追问、改问具体卡点时，孩子更愿意表达真实困难",
      "confidence": 0.72
    }
  ]
}
```

# 十三、触发条件八：家长长期关注目标发生变化

## 1. 定义

家长对孩子的长期关注重点发生调整。

## 2. 示例

旧目标：

```text
学习主动性。
```

新输入：

```text
我之前以为我只是想让他自觉，但现在发现我更怕的是他什么都不跟我说。
```

处理：

```text
提高“亲子信任”权重；保留但轻微降低“学习主动性”权重。
```

## 3. 前台表达

```text
这个信息会让前面的长期关注更清楚一点。之前更像是学习主动性，现在看，亲子信任也是很重要的一条。
```

## 4. 写入

```json
{
  "long_term_goal_updates": [
    {

      "action": "decrease_weight",

    }
  ],
  "correction_candidates": [
    {
      "old_judgment": "家长主要关注孩子学习主动性",
      "new_judgment": "家长同时高度关注亲子信任和孩子是否愿意说真实想法",
      "correction_type": "add_exception",
      "confidence": 0.8
    }
  ]
}
```

# 十四、纠偏类型

纠偏分为 5 类：

```text
1. 降权 deprecate_old
2. 替换 replace_old
3. 缩小范围 narrow_scope
4. 拆分判断 split_judgment
5. 增加例外 add_exception
```

---

## 1. 降权 deprecate_old

适用：

- 家长反馈“不太像”；
- 新事实使旧判断不稳；
- 旧判断证据不足。

示例：

```text
旧判断：孩子拖延和休息边界有关。
新事实：孩子根本没有进入任务。
处理：降低休息边界解释权重。
```

---

## 2. 替换 replace_old

适用：

- 旧判断明显不符合新事实；
- 多次新信息指向另一个解释；
- 家长确认新解释更准确。

示例：

```text
旧判断：孩子不想学。
新判断：孩子不知道从哪一步开始。
```

---

## 3. 缩小范围 narrow_scope

适用：

- 旧判断在部分场景成立，但不能泛化。

示例：

```text
旧判断：孩子拿手机是逃避学习。
新判断：学习前拿手机可能是逃避，完成后拿手机可能是恢复。
```

---

## 4. 拆分判断 split_judgment

适用：

- 旧判断太笼统；
- 同一个行为在不同场景含义不同。

示例：

```text
“拖作业”拆成：开始前拖、写到一半停、订正抗拒、检查回避。
```

---

## 5. 增加例外 add_exception

适用：

- 旧判断大体成立，但出现一个重要例外。

示例：

```text
孩子被追问时容易沉默，但当家长问“卡在哪一步”时，能表达具体困难。
```

---

# 十五、纠偏优先级

当多种纠偏都可能时，按以下顺序选择：

```text
1. 当前具体事实优先
2. 家长明确反馈优先
3. 多次近期记录优先
4. 孩子问卷优先于旧诊断卡
5. 高置信新判断优先于低置信旧判断
6. 能解释多个现象的新判断优先
7. 不直接删除旧判断，优先缩小范围或增加例外
```

---

# 十六、前台纠偏表达规则

## 1. 纠偏要自然，不要系统化

推荐：

```text
我改一下前面的理解。
这个信息会让之前那个判断更谨慎一点。
那我先把前面那个方向降一下权重。
这次更适合换一个角度理解。
```

避免：

```text
系统已纠偏。
旧画像失效。
之前判断错误。
模型判断更新。
```

---

## 2. 纠偏要具体

不要只说：

```text
我调整一下。
```

要说明调整方向：

```text
我改一下前面的理解。这次可能不是休息边界的问题，更像是学习启动本身没有起来。
```

---

## 3. 纠偏不做长篇辩解

家长否定时，不要解释系统为什么之前那样判断。

只需：

```text
接受修正 → 降权旧判断 → 重新确认一个关键事实
```

---

## 4. 纠偏时最多问一个问题

推荐：

```text
还想问您一个细节：他当时更像是不知道从哪开始，还是明知道要做但就是不愿意坐下？
```

不推荐：

```text
那他当时几点开始？什么科目？之前休息了吗？您说了什么？他有没有顶嘴？
```

---

# 十七、纠偏写入格式

推荐结构：

```json
{
  "correction_candidates": [
    {
      "old_judgment_id": "entry_001",
      "old_judgment": "孩子拿手机主要是逃避学习",
```

# 十八、纠偏后的数据库处理

后端收到 `correction_candidates` 后，不应只写日志，还要更新相关记忆状态。

## 1. 处理顺序

```text
1. 找到 old_judgment 对应画像或模式
2. 判断 correction_type
3. 更新旧条目的 confidence / status / scope
4. 新增或增强 new_judgment
5. 写入 correction_logs
6. 写入 profile_update_log
7. 返回 memory_note_final
```

---

## 2. 不同 correction_type 的处理

### deprecate_old

```text
旧条目 confidence 降低；
status 可从 active 改为 hypothesis / conflicted / deprecated。
```

### replace_old

```text
旧条目 status 改为 deprecated；
新条目写入 active 或 hypothesis。
```

### narrow_scope

```text
旧条目保留，但增加适用范围说明；
新增新场景条目。
```

### split_judgment

```text
旧条目标记为 split；
新增多个更具体条目。
```

### add_exception

```text
旧条目保留；
新增 exception 或 growth_record。
```

# 十九、前端 memory_note 规则

纠偏写入成功后，前端可展示：

```text
已调整前面的一个判断
```

只有后端真实写入 `correction_logs` 或 `profile_update_log` 后才能显示。

不能仅因为 Agent 说了“我改一下”就展示。

# 二十一、不要触发纠偏的情况

以下情况不应触发纠偏：

## 1. 只是补充同方向证据

旧判断：

```text
孩子被追问时容易沉默。
```

新信息：

```text
今天又是这样。
```

处理：

```text
增强旧画像，不纠偏。
```

## 2. 信息太模糊

家长说：

```text
好像也不是这样。
```

但没有具体事实。

处理：

```text
轻问一个事实，不急着写纠偏。
```

## 3. 家长只是情绪化反驳

```text
你们说得都不对，我都不知道怎么办了。
```

处理：

```text
先接住情绪，必要时暂停判断。
```

## 4. 新事实无法定位场景

```text
最近变化挺大的。
```

处理：

```text
问一个关键细节，不写纠偏。
```

# 二十二、纠偏与阶段复盘的关系

如果纠偏频繁出现，说明现有画像可能整体需要重整。

触发阶段复盘建议的情况：

- 同一旧判断被多次降权；
- 多个画像条目进入 conflicted；
- 孩子问卷大幅改变家长观察；
- 近期成长记录持续挑战首次诊断卡；
- 家长连续反馈“不太像”；
- 家庭互动模式出现明显新方向。

输出：

```json
{
  "should_trigger_review": true,
  "review_reason": "近期多条记录显示旧画像需要阶段性重整"
}
```

前台：

```text
这几次信息放在一起，已经不太适合只看单次事件了。后面可以帮您整理一次最近阶段的小观察，把孩子这段时间的变化单独拎出来。
```

---

# 二十三、纠偏质量检查

每次纠偏前，Agent 必须检查：

```text
1. 新信息具体吗？
2. 它挑战的是哪个旧判断？
3. 是完全冲突，还是只需要缩小范围？
4. 旧判断是否仍在某些场景成立？
5. 需要降权、替换、拆分，还是增加例外？
6. 前台有没有自然说明，不像系统报错？
7. 是否需要问一个关键问题？
8. 是否写入 correction_candidates？
9. 是否需要同步更新 pending_observations / growth_records / profile_entries？
```

---

## 二十四、最终一句话

纠偏机制决定了「对话实验室」是不是一个真正会学习的系统。

它不是为了频繁推翻自己，而是为了在新事实出现时，让旧判断变得更具体、更克制、更贴近这个孩子。

> 好的纠偏，不会让家长觉得系统不稳定；它会让家长觉得：这个系统真的会听新信息，也真的在越来越懂我家孩子。
