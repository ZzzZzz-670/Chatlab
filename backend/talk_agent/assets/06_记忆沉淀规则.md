# 06_记忆沉淀规则.md

## 一、文档定位

本文定义「对话实验室」日常对话 Agent 如何把对话中的有效信息沉淀为长期可用的结构化记忆。

记忆沉淀不是简单保存聊天记录，也不是把家长说的每句话都塞进数据库。它要服务于：

- 日常轻回应；
- 孩子小档案更新；
- 成长信号记录；
- 家长长期关注目标；
- 沟通预演；
- 纠偏；
- 周期性小观察；
- 阶段复盘；
- 首次诊断卡的持续验证与修正。

一句话：

> 记忆沉淀的目标不是“记得越多越好”，而是把家长输入中真正能帮助后续判断孩子、理解家长和识别家庭互动的信息，分层、降噪、带置信度地存下来。

---

## 二、核心原则

## 1. 记忆不是聊天历史

聊天历史是原始材料，记忆是加工后的结构化结果。

错误理解：

```text
把所有对话都长期塞进上下文。
```

正确理解：

```text
从对话中抽取事实、变化、目标、画像、互动模式和纠偏记录，形成结构化小档案。
```

聊天历史用于回看，结构化记忆用于后续判断。

---

## 2. 不把家长评价直接写入孩子画像

这是记忆沉淀最重要的原则。

家长说：

```text
他就是懒。
```

不能写入：

```text
孩子懒。
```

应拆成：

```text
事实：孩子在某任务上启动延迟。
家长评价：家长将其理解为懒。
候选解释：启动困难、任务边界不清、疲惫、对安排抵触、怕暴露短板。
待观察点：确认拖延发生在开始前，还是写到一半后。
```

记忆库里应写：

```text
孩子在作业启动前存在延迟，需要继续确认原因。
```

或：

```text
家长倾向将孩子作业启动延迟理解为不自觉。
```

而不是：

```text
孩子懒。
```

---

## 3. 记忆必须分层

同一句话可能拆成多个层级。

例如：

家长说：

```text
我问他为什么不写，他就不说话，真的很气人。
```

可拆成：

```text
事实：家长问孩子为什么不写，孩子沉默。
家长情绪：生气、无力。
孩子行为：被问原因时沉默。
候选解释：孩子可能在降低冲突，或不知道怎么解释。
家庭互动候选：追问—沉默循环。
待观察点：确认沉默前家长最后一句是问原因，还是提醒必须做。
```

不同内容应进入不同库，而不是全部写进一个“孩子画像”。

---

## 4. 单次事件不直接变成稳定画像

单次事件最多是：

- 成长记录；
- 待观察点；
- 候选画像；
- 候选家庭互动模式；
- 候选家长理解。

只有多次出现、家长确认、孩子问卷支持、与旧画像一致时，才适合增强为稳定画像。

---

## 5. 首次诊断卡是起点，不是终点

首次诊断型 Agent 生成的孩子理解卡，应作为：

```text
initial_hypothesis
```

而不是：

```text
permanent_truth
```

日常 Agent 后续要持续完成：

- 验证；
- 补充；
- 降权；
- 修正；
- 拆分；
- 替换；
- 形成更稳定的小档案。

---

## 6. 记忆要允许纠偏

好的记忆系统不是只会越存越多，而是能调整旧判断。

需要支持：

- 降权；
- 缩小适用范围；
- 合并；
- 拆分；
- 标记冲突；
- 写入例外；
- 触发阶段复盘。

例如：

旧记忆：

```text
孩子拿手机主要是逃避学习。
```

新信息：

```text
最近三次都是完成一段任务后拿手机，并且能按时回来。
```

应更新为：

```text
旧判断缩小适用范围：学习前拿手机可能是逃避；完成任务后拿手机更可能是恢复需求。
```

---

# 三、记忆库总体结构

建议将日常 Agent 记忆沉淀分为 8 类：

```text
1. 孩子基础画像 child_profiles
2. 孩子画像条目 profile_entries
3. 近期成长记录 growth_records
4. 待观察点 pending_observations
5. 家长长期关注 long_term_goals
6. 家长理解记录 parent_profile
7. 家庭互动模式 family_interaction_patterns
8. 纠偏记录 correction_logs
```

辅助记录：

```text
9. 孩子问卷记录 questionnaire_records
10. 沟通预演记录 rehearsal_records
11. 画像更新日志 profile_update_log
12. 原始对话索引 conversation_events
```

---

# 四、记忆类型说明

## 1. child_profiles：孩子主画像

用于存储一个孩子的基础概览。

示例字段：

```json
{
  "child_id": "child_001",
  "family_id": "family_001",
  "nickname": "小尹",
  "grade": "高二",
  "school_stage": "高中",
  "profile_summary": "孩子在被连续追问时容易沉默，作业启动前阻力较大，对任务边界和休息安排较敏感。",
  "profile_completeness": 0.68,
  "created_at": "2026-05-10T20:00:00+08:00",
  "updated_at": "2026-05-15T20:00:00+08:00"
}
```

使用规则：

- 只存摘要，不存所有细节；
- 由多个 `profile_entries` 汇总生成；
- 可以随日常记录持续更新；
- 不应频繁大改，除非出现多条纠偏记录或阶段复盘。

---

## 2. profile_entries：孩子画像条目

用于存储孩子较稳定的特点、倾向和场景反应。

示例：

```json
{
  "entry_id": "entry_001",
  "family_id": "family_001",
  "child_id": "child_001",
  "category": "communication",
  "content": "孩子在被连续追问时容易沉默，可能是在降低冲突",
  "confidence": 0.78,
  "status": "active",
  "source": "diagnosis_and_chat",
  "evidence_count": 3,
  "last_confirmed_at": "2026-05-15T20:00:00+08:00"
}
```

可写入类型：

- 学习状态；
- 作业启动方式；
- 情绪反应；
- 沟通特点；
- 休息边界；
- 手机使用功能；
- 兴趣能量来源；
- 学校同伴状态；
- 自我管理方式；
- 压力反应；
- 家庭互动下的孩子反应。

不可写入：

```text
孩子懒。
孩子不懂事。
孩子没责任感。
孩子玻璃心。
孩子沉迷手机。
孩子故意气家长。
```

---

## 3. growth_records：近期成长记录

用于记录近期具体变化。

示例：

```json
{
  "record_id": "growth_001",
  "family_id": "family_001",
  "child_id": "child_001",
  "scene_type": "communication",
  "signal_type": "表达开放",
  "content": "孩子在作业场景中说出“不知道从哪开始”，相比过去沉默有变化",
  "direction": "positive",
  "importance": "high",
  "source": "chat",
  "confidence": 0.78,
  "created_at": "2026-05-15T20:00:00+08:00"
}
```

使用规则：

- 单次具体变化优先写这里；
- 不直接升级为稳定画像；
- 多条同向成长记录可增强画像；
- 可用于周期性小观察。

---

## 4. pending_observations：待观察点

用于记录重要但尚不确定的判断方向。

示例：

```json
{
  "observation_id": "obs_001",
  "family_id": "family_001",
  "child_id": "child_001",
  "content": "确认孩子拿手机更偏学习前逃避，还是完成任务后的恢复",
  "related_scene": "phone_rest",
  "priority": "high",
  "status": "active",
  "created_at": "2026-05-13T20:00:00+08:00"
}
```

适合写入：

- 两种解释都可能；
- 新信息可能改变旧判断；
- 孩子问卷和家长观察不一致；
- 家长评价缺事实支撑；
- 旧诊断卡需要验证；
- 长期目标需要后续场景观察。

---

## 5. long_term_goals：家长长期关注目标

用于记录家长长期希望孩子发展的方向。

示例：

```json
{
  "goal_id": "goal_001",
  "family_id": "family_001",
  "child_id": "child_001",
  "goal_name": "责任感与抗压能力",
  "goal_category": "resilience",
  "weight": 0.82,
  "related_scenes": ["作业启动", "手机规则", "考试复盘", "周末安排"],
  "status": "active",
  "last_triggered_at": "2026-05-15T20:00:00+08:00"
}
```

可记录目标：

- 成绩稳定；
- 学习主动性；
- 责任感；
- 抗压能力；
- 心理健康；
- 人格健全；
- 综合素质；
- 亲子信任；
- 自我管理；
- 兴趣发展；
- 社交能力。

---

## 6. parent_profile：家长理解记录

用于记录家长的目标、偏好、焦虑来源和沟通习惯。

示例：

```json
{
  "parent_entry_id": "parent_001",
  "family_id": "family_001",
  "category": "communication_style",
  "content": "家长在作业场景中容易连续确认原因，希望尽快判断孩子为什么不写",
  "confidence": 0.65,
  "status": "active",
  "source": "chat",
  "updated_at": "2026-05-15T20:00:00+08:00"
}
```

可写：

```text
家长高度关注高二成绩稳定。
家长希望孩子更有责任感。
家长偏好简洁、具体、可执行回复。
家长在作业场景中倾向连续确认原因。
家长近期对手机问题焦虑较高。
```

不可写：

```text
家长控制欲强。
家长过度焦虑。
家长不会沟通。
家长强势。
家长有问题。
```

---

## 7. family_interaction_patterns：家庭互动模式

用于记录亲子之间反复出现的互动循环。

示例：

```json
{
  "pattern_id": "pattern_001",
  "family_id": "family_001",
  "child_id": "child_001",
  "pattern_name": "追问—沉默循环",
  "content": "家长越想确认原因，越容易连续追问；孩子在这种场景下更容易沉默或表面答应",
  "scene": "作业拖延",
  "confidence": 0.76,
  "evidence_count": 3,
  "status": "active",
  "last_seen_at": "2026-05-15T20:00:00+08:00"
}
```

常见模式：

- 追问—沉默循环；
- 加任务—磨蹭循环；
- 认错—失信循环；
- 期待—压力循环；
- 手机冲突循环；
- 边界争夺循环；
- 讲道理—关闭循环；
- 检查—暴露—回避循环；
- 信任下降循环；
- 乖巧—压抑—反弹循环。

---

## 8. correction_logs：纠偏记录

用于记录系统对旧判断的调整。

示例：

```json
{
  "correction_id": "corr_001",
  "family_id": "family_001",
  "child_id": "child_001",
  "old_judgment": "孩子拿手机主要是逃避学习",
  "new_judgment": "孩子拿手机在完成任务后也可能是恢复需求",
  "correction_type": "narrow_scope",
  "reason": "最近三次记录显示孩子多在完成一段任务后拿手机",
  "confidence": 0.72,
  "created_at": "2026-05-15T20:00:00+08:00"
}
```

纠偏类型：

| 类型 | 含义 |
|---|---|
| `deprecate_old` | 降低旧判断权重 |
| `replace_old` | 用新判断替换旧判断 |
| `narrow_scope` | 缩小旧判断适用范围 |
| `split_judgment` | 将旧判断拆成多个场景 |
| `add_exception` | 增加例外情况 |

# 五、记忆分层规则

日常 Agent 处理家长输入时，应把信息分成以下层级。

## 1. L1：原始事实

家长明确描述过的具体事件。

示例：

```text
孩子写完一页后拿手机。
孩子被问为什么不写时沉默。
孩子说“知道了”，但后续没有执行。
```

处理：

```text
可写 growth_records 或 conversation_events。
```

---

## 2. L2：观察标签

对事实的轻分类。

示例：

```text
作业启动延迟。
完成任务后拿手机。
被追问后沉默。
表面答应但未执行。
```

处理：

```text
可写 growth_records / pending_observations。
```

---

## 3. L3：候选解释

对行为背后原因的可能理解。

示例：

```text
孩子可能在用沉默降低冲突。
孩子可能担心做完后继续被加任务。
孩子拿手机可能是完成任务后的恢复需求。
```

处理：

```text
可写 pending_observations 或低置信 profile_entries。
```

---

## 4. L4：稳定画像

多次验证、家长确认或孩子问卷支持后的特点。

示例：

```text
孩子在被连续追问时容易沉默，可能是在降低冲突。
孩子对任务边界较敏感，做完后是否能真正结束会影响启动意愿。
```

处理：

```text
写 profile_entries。
```

---

## 5. L5：家庭互动模式

孩子行为和家长动作之间形成的循环。

示例：

```text
追问—沉默循环。
加任务—磨蹭循环。
认错—失信循环。
```

处理：

```text
写 family_interaction_patterns。
```

---

## 六、写入决策规则

每轮对话后，Agent 必须在内部判断：

```text
这句话应该写入哪里？
是否应该写入？
是否只写候选？
是否需要等待更多信息？
是否会污染画像？
```

---

## 1. 写入 growth_records 的条件

适合写入：

- 有具体事件；
- 和孩子旧状态有差异；
- 对后续理解有价值；
- 是近期变化；
- 不足以成为稳定画像。

示例：

```text
孩子今天主动提到学校里的事。
孩子这次说出“不知道从哪开始”。
孩子完成一段任务后主动提出休息十分钟。
```

不适合写入：

```text
家长很烦。
孩子就是懒。
孩子以后肯定不行。
```

---

## 2. 写入 profile_entries 的条件

适合写入：

- 多次出现；
- 证据具体；
- 置信度较高；
- 家长确认有点像；
- 孩子问卷支持；
- 能帮助后续判断。

示例：

```text
孩子在被连续追问时容易沉默，可能是在降低冲突。
```

不适合写入：

- 单次事件；
- 家长情绪化评价；
- 原因不明的行为；
- 置信度低于 0.6 的判断。

---

## 3. 写入 pending_observations 的条件

适合写入：

- 当前信息不足；
- 存在两个以上可能解释；
- 该问题后续很重要；
- 与旧画像可能冲突；
- 家长评价缺事实支撑；
- 孩子问卷和家长观察不一致。

示例：

```text
确认孩子作业拖延主要发生在开始前，还是写到一半后。
```

---

## 4. 写入 long_term_goals 的条件

适合写入：

- 家长明确表达长期目标；
- 家长多次反复提到某类关注；
- 当前事件与长期培养方向有关。

示例：

```text
希望孩子更有责任感。
希望孩子心理健康一点。
希望孩子别只会考试。
希望孩子有抗压能力。
```

---

## 5. 写入 parent_profile 的条件

适合写入：

- 家长表达了稳定偏好；
- 家长多次呈现同类沟通习惯；
- 家长长期关注某类问题；
- 家长反馈了对 Agent 输出的偏好；
- 家长近期压力状态会影响回复方式。

示例：

```text
家长偏好简洁、具体、可执行的回复。
家长在作业场景中容易连续确认原因。
家长近期对手机问题焦虑较高。
```

---

## 6. 写入 family_interaction_patterns 的条件

适合写入：

- 同类亲子互动出现两次以上；
- 有家长动作和孩子反应；
- 与孩子画像或家长画像吻合；
- 家长确认有点像；
- 孩子问卷支持。

示例：

```text
家长连续追问原因后，孩子更容易沉默或表面答应。
```

---

## 7. 写入 correction_logs 的条件

适合写入：

- 家长明确否定旧判断；
- 新信息与旧画像冲突；
- 多次新记录显示旧判断不再适用；
- 孩子问卷改变了旧理解；
- 旧判断需要缩小适用范围。

示例：

```text
旧判断“手机主要是逃避学习”需要缩小范围：完成任务后拿手机更可能是恢复需求。
```

# 七、置信度规则

每条记忆都应带 `confidence`。

## 1. 置信度建议

| 置信度 | 含义 | 处理 |
|---|---|---|
| 0.0–0.4 | 信息不足 | 不写稳定画像，最多写待观察 |
| 0.4–0.6 | 有方向但不稳 | 写待观察或候选画像 |
| 0.6–0.75 | 较有依据 | 可写画像候选或增强旧画像 |
| 0.75–0.9 | 多次验证 | 可写稳定画像 |
| 0.9–1.0 | 强确认 | 高置信稳定画像 |

---

## 2. 提高置信度的因素

- 多次出现；
- 家长确认“有点像”；
- 孩子问卷支持；
- 与近期记录一致；
- 能解释多个行为；
- 有具体孩子原话；
- 有具体时间和场景。

---

## 3. 降低置信度的因素

- 只有家长评价，没有事实；
- 信息来自强情绪状态；
- 与孩子问卷冲突；
- 与近期记录冲突；
- 只出现一次；
- 场景不清；
- 旧判断被家长否定。

---

# 八、状态字段规则

建议每条画像或模式有 `status`。

| status | 含义 |
|---|---|
| `active` | 当前有效 |
| `hypothesis` | 候选假设 |
| `pending` | 待观察 |
| `confirmed` | 已确认 |
| `deprecated` | 已降权 |
| `conflicted` | 存在冲突 |
| `archived` | 归档，不再默认调用 |

---

## 状态转换

```text
hypothesis → active
条件：多次验证 / 家长确认 / 孩子问卷支持

active → confirmed
条件：高频出现 + 多来源支持

active → conflicted
条件：新信息明显冲突

conflicted → deprecated
条件：多次新证据证明旧判断不适用

active → archived
条件：长期未出现且不再相关
```

---

# 九、合并规则

## 1. 什么时候合并

以下情况应合并，而不是新增：

- 内容高度相似；
- 同一场景同一解释；
- 同一长期目标；
- 同一家庭互动循环；
- 同一待观察点已有记录。

示例：

已有：

```text
孩子在被连续追问时容易沉默。
```

新候选：

```text
孩子被问为什么不写时沉默，可能是在降低冲突。
```

处理：

```text
合并到原条目，提高置信度，增加 evidence_count。
```

---

## 2. 什么时候新增

以下情况应新增：

- 场景不同；
- 行为不同；
- 解释不同；
- 旧条目无法覆盖新信息；
- 新信息是旧判断的例外；
- 新信息提示新的长期目标。

示例：

已有：

```text
孩子学习前拿手机可能是逃避压力。
```

新信息：

```text
孩子完成一段任务后拿手机，并能按时回来。
```

处理：

```text
新增或拆分：完成任务后拿手机可能是恢复需求。
```

---

## 3. 什么时候拆分

旧判断过于笼统时，应拆分。

示例：

旧：

```text
孩子沉迷手机。
```

拆成：

```text
学习前拿手机：可能是逃避压力。
完成任务后拿手机：可能是恢复需求。
无任务时也停不下：可能是即时反馈依赖。
睡前拿手机：可能是情绪缓冲或睡眠节律问题。
```

---

# 十、纠偏规则

## 1. 纠偏不是删除

除非明显错误，不应直接删除旧记忆。

优先处理方式：

- 降权；
- 缩小适用范围；
- 增加例外；
- 拆分；
- 标记冲突；
- 写入新判断。

---

## 2. 纠偏类型

| 类型 | 说明 | 示例 |
|---|---|---|
| `deprecate_old` | 降低旧判断权重 | 旧判断不再适用 |
| `replace_old` | 用新判断替换旧判断 | 旧判断明显错误 |
| `narrow_scope` | 缩小适用范围 | 只在学习前手机成立 |
| `split_judgment` | 拆成多个场景 | 手机不同时间含义不同 |
| `add_exception` | 增加例外 | 某场景下孩子不会沉默 |

---

## 3. 前台纠偏表达

推荐：

```text
我改一下前面的理解。
这个信息会让之前那个判断更谨慎一点。
那我先把前面那个方向降一下权重。
这次更适合换一个角度理解。
```

避免：

```text
系统纠偏。
之前判断错误。
旧画像失效。
```

# 十五、记忆读取规则

写入只是第一步，更重要的是后续能正确读取。

每轮日常 Agent 读取时，按以下优先级：

```text
当前场景强相关记忆
>
近期确认记忆
>
高置信稳定画像
>
待观察点
>
家长长期目标
>
纠偏记录
>
首次诊断卡
```

不要全量读取所有记忆。

推荐读取数量：

```text
profile_entries：最多 10 条
growth_records：最近 / 相关最多 5 条
pending_observations：最多 5 条
long_term_goals：最多 5 条
parent_profile：最多 5 条
family_interaction_patterns：最多 5 条
correction_logs：最多 3 条
```

# 十六、禁止事项

## 1. 禁止记忆污染

不要把以下内容写成孩子稳定画像：

```text
孩子懒。
孩子废了。
孩子没救。
孩子太叛逆。
孩子心理有问题。
孩子就是故意的。
```

## 2. 禁止过度记录

不是每句话都要写入。

以下不必写入长期记忆：

- 一次普通寒暄；
- 没有事实的情绪宣泄；
- 与孩子无关的临时信息；
- 无后续复用价值的琐事；
- 已经存在且无新增的信息。

## 3. 禁止只增不减

记忆系统必须允许：

- 降权；
- 归档；
- 标记冲突；
- 纠偏；
- 删除明显错误候选。

## 4. 禁止前端伪造记忆更新

只有后端写入成功，才能展示：

```text
已记录
已更新
已加入
已调整
```

---

# 十七、最低验收标准

记忆沉淀规则完成后，应满足：

1. 家长评价不会直接污染孩子画像；
2. 单次事件不会直接变成稳定画像；
3. 孩子、家长、家庭互动三类记忆能分开存；
4. 成长信号能进入 growth_records；
5. 长期目标能进入 long_term_goals；
6. 待观察点能驱动后续轻追问；
7. 首次诊断卡能被日常记录持续验证和修正；
8. 家长反馈“不太像”能触发降权或纠偏；
9. 前端小字必须对应真实写入日志；
10. 换新会话后仍能通过 family_id + child_id 调用同一套记忆；
11. 记忆能合并、拆分、降权、归档；
12. 后续输出能明显体现“系统越来越懂这个家庭”。

---

## 十八、最终一句话

记忆沉淀不是把对话存下来，而是把对话中真正有判断价值的信息变成可复用、可验证、可纠偏的家庭理解。

> 好的记忆系统不只是记住孩子说过什么，更要知道哪些是事实、哪些是假设、哪些需要继续观察，哪些旧判断已经该改了。
