# 04B_家长叙述拆解规则.md

## 一、文档定位

本文定义「对话实验室」日常对话 Agent 如何从家长输入中拆出有效信息。

它是 `04A_孩子与家长理解引擎规则.md` 的下位规则，服务于以下前台功能：

- 轻回应；
- 成长信号抽取；
- 孩子小档案更新；
- 家长长期关注识别；
- 沟通预演；
- 纠偏；
- 周期性小观察。

本文不是为了让前台输出变得更复杂，而是为了让 Agent 在后台更准确地理解家长、理解孩子、减少误判。

核心原则：

> 家长说的话不能被整体当成事实。Agent 必须先拆出事实、情绪、评价、推测、目标和缺失信息，再决定如何回应、追问和写入记忆。

---

## 二、为什么必须拆解家长叙述

家长在真实对话中很少只提供客观事实。大多数输入会同时包含：

- 孩子发生了什么；
- 家长当下的情绪；
- 家长对孩子的解释；
- 家长对未来的担心；
- 家长希望孩子变成什么样；
- 家长对自己做法的辩解或困惑；
- 关键但未说完整的信息。

例如：

```text
他就是不自觉，天天拖作业，我一催他就烦，我真的不知道怎么管了。
```

这句话不能直接理解成“孩子不自觉”。

应该拆成：

```text
事实：孩子近期存在拖作业现象；家长催促后孩子烦躁。
家长情绪：无力、焦虑、烦躁。
家长评价：孩子不自觉。
孩子行为：拖延、被催后烦躁。
家长目标：希望知道怎么管、怎么推进作业。
缺失信息：拖延发生在开始前还是写到一半后；是否所有作业都拖；孩子烦躁前家长具体怎么催。
```

拆解的目的不是批评家长，而是防止 Agent 把家长的情绪性解释直接写入孩子画像。

---

## 三、家长叙述的六类信息

日常 Agent 每轮要优先拆出六类信息。

| 类型 | 定义 | 是否可直接入库 | 说明 |
|---|---|---|---|
| 客观事实 | 具体发生的事情 | 可进入成长记录 | 需要尽量具体 |
| 孩子行为 | 孩子做了什么、说了什么 | 可作为画像依据 | 需结合场景 |
| 家长情绪 | 家长的感受和状态 | 不写入孩子画像 | 可写入家长状态/回应语气 |
| 家长评价 | 家长对孩子的定性 | 不可直接入库 | 只能作为家长解释 |
| 家长推测 | 家长猜孩子为什么这样 | 不可直接入库 | 需验证 |
| 家长目标 | 家长期待改变什么 | 可写入长期关注 | 需要归类和权重 |

---

## 四、六类信息的详细规则

## 1. 客观事实

### 定义

家长描述的、相对可验证的具体事件。

示例：

```text
昨天晚上写数学，他坐了半小时还没开始。
他写完一页后拿手机。
他说“知道了”，但后面没有改。
这周有三天睡得比平时晚。
```

### 处理方式

- 可以写入 `growth_records`；
- 可以作为 `profile_entries` 的证据；
- 如果事实不完整，优先形成待观察点；
- 不能脱离时间、场景和前后顺序过度解释。

### 抽取格式

```json
{
  "fact": "孩子写完一页后拿手机",
  "scene": "作业与手机",
  "time_context": "晚上作业后",
  "source": "parent_chat",
  "completeness": "medium"
}
```

---

## 2. 孩子行为

### 定义

孩子在事件中的具体反应，包括动作、语言、情绪表现和互动方式。

常见类型：

| 类型 | 示例 |
|---|---|
| 动作 | 拖着不写、拿手机、回房间 |
| 语言 | “知道了”“随便”“没事”“我不会” |
| 情绪 | 烦躁、哭、沉默、顶嘴 |
| 学习反应 | 不问问题、写一会停、错题抗拒 |
| 沟通反应 | 表面答应、沉默、转移话题 |
| 恢复方式 | 发呆、听歌、运动、找朋友 |

### 处理方式

孩子行为是理解孩子的主要依据，但不能只看表面。

例如：

```text
孩子沉默
```

不能直接解释为“不配合”。

可能是：

- 不知道怎么解释；
- 说了也觉得没用；
- 想让冲突先降下来；
- 怕越说越被追问；
- 情绪太满，暂时说不出。

### 抽取格式

```json
{
  "child_behavior": "被问为什么不写时沉默",
  "surface_meaning": "不回应",
  "possible_functions": ["降低冲突", "避免继续被追问", "不知道怎么解释"],
  "needs_more_info": true
}
```

---

## 3. 家长情绪

### 定义

家长对事件的感受和状态。

常见表达：

```text
我真的很烦。
我受不了了。
我很担心。
我不知道怎么办。
我有时候也觉得自己是不是太急了。
```

### 处理方式

- 用于调整回复语气；
- 可进入 `parent_profile` 的“近期压力状态”；
- 不直接写入孩子画像；
- 不要用家长情绪替代孩子事实。

### 正确处理

家长说：

```text
我真的受不了他这样拖了。
```

Agent 应识别：

```text
家长当前情绪强，回复要先接住，不适合马上长篇建议。
```

可回复：

```text
您这个烦是有原因的，反复催、反复没推进，家长很容易觉得自己一直在原地消耗。我们先把这次具体发生的位置确认一下。
```

---

## 4. 家长评价

### 定义

家长对孩子的定性判断。

常见表达：

```text
他就是懒。
他没有责任感。
他太玻璃心。
他一点也不自觉。
他就是故意气我。
他沉迷手机。
他敷衍我。
```

### 处理方式

家长评价不能直接写入孩子画像。

必须拆成：

```text
评价背后的具体事实是什么？
这个评价说明家长在担心什么？
孩子行为是否还有其他解释？
```

### 处理示例

| 家长评价 | 不能写入 | 应拆成 |
|---|---|---|
| 他就是懒 | 孩子懒 | 某任务启动延迟；家长解释为懒；原因待确认 |
| 他没有责任感 | 孩子无责任感 | 某场景中未承担任务；家长期望责任感 |
| 他沉迷手机 | 孩子沉迷手机 | 手机出现时间、使用功能、冲突前后状态待确认 |
| 他敷衍我 | 孩子敷衍 | 表面答应但后续未执行；可能是在降低冲突 |
| 他玻璃心 | 孩子脆弱 | 被评价后情绪反应强；需确认触发点 |

---

## 5. 家长推测

### 定义

家长猜测孩子为什么这样。

常见表达：

```text
他是不是故意的？
他是不是就是不想学？
他是不是觉得我烦？
他是不是心理有问题？
他是不是叛逆期？
```

### 处理方式

- 不直接确认；
- 不直接否定；
- 转成候选解释；
- 回到可观察事实。

### 推荐回应

```text
这个可能性可以先放着，但我不急着直接定成“故意”。更关键的是，他当时是在什么节点开始不配合：任务开始前，还是已经写了一段以后？
```

---

## 6. 家长目标

### 定义

家长真正希望孩子改变或发展的方向。

常见表达：

```text
我希望他更自觉。
我希望他能抗压。
我希望他心理健康一点。
我不想他只会考试。
我希望他更有责任感。
我想让他对学习有点内驱力。
```

### 处理方式

- 写入 `long_term_goals`；
- 根据提及频率调整权重；
- 后续相关场景中自然带回；
- 不要马上给宏大方案。

### 抽取格式

```json
{
  "goal_name": "责任感与自我管理",
  "goal_category": "responsibility",
  "source": "parent_chat",
  "weight_delta": 0.15,
  "related_scenes": ["作业启动", "周末安排", "手机规则", "考试复盘"]
}
```

---

## 五、缺失信息识别规则

很多家长输入会缺关键事实。Agent 要判断“缺的是什么”，而不是随便追问。

## 1. 常见缺失信息

| 场景 | 常缺信息 | 为什么重要 |
|---|---|---|
| 作业拖延 | 拖在开始前还是中途 | 区分启动困难和过程困难 |
| 手机冲突 | 手机出现时间点 | 区分逃避、恢复、即时反馈依赖 |
| 孩子沉默 | 前一句家长说了什么 | 判断是否被追问/评价触发 |
| 情绪爆发 | 爆发前是否有累积事件 | 判断当前事件还是长期积压 |
| 成绩退步 | 哪一科、哪类题、持续多久 | 区分能力漏洞和状态问题 |
| 不问问题 | 是不会问还是不敢问 | 区分方法问题和自尊压力 |
| 说“没事” | 睡眠、学校、同伴是否变化 | 判断是真没事还是关闭表达 |

## 2. 补问规则

每轮最多问一个问题。

问题要满足：

- 家长能凭最近经历回答；
- 能区分至少两个候选解释；
- 不带强暗示；
- 不问心理原因；
- 不连续追问。

推荐问法：

```text
还想问您一个细节：他是坐下前一直拖，还是写了一段之后才慢下来？
```

不推荐：

```text
他是不是怕失败？
他是不是在保护自尊？
他是不是觉得你们控制太多？
```

## 六、家长高价值关键词识别

某些词往往提示重要线索。Agent 要在后台标记，但前台不机械复述。

## 1. 学习类关键词

```text
不自觉、拖、磨蹭、不会也不问、都懂、错题、背诵、检查、订正、效率低、假努力、刷难题
```

可能指向：

- 启动困难；
- 暴露短板压力；
- 任务边界不清；
- 自尊保护；
- 学科真实卡点；
- 表面努力维持形象。

## 2. 手机娱乐类关键词

```text
沉迷、控制不住、一有空就玩、写完就拿、睡前刷、偷偷玩、不让就急
```

可能指向：

- 即时反馈依赖；
- 恢复时间不足；
- 自主权争夺；
- 睡眠节律问题；
- 学习前逃避压力；
- 完成任务后的休息边界。

## 3. 沟通类关键词

```text
不说话、顶嘴、敷衍、知道了、随便、没事、我错了、下次改
```

可能指向：

- 降低冲突；
- 表面认错；
- 不知道怎么解释；
- 真实想法没有出口；
- 对沟通失去信任；
- 怕越说越被追问。

## 4. 家长投入类关键词

```text
我花了很多钱、我已经够给空间、我都是为他好、我不盯不行、我没有逼他
```

可能指向：

- 家长付出感强；
- 家长期待和孩子感受存在差异；
- 孩子可能感到学习背后有债感；
- 家长可能低估孩子接收到的压力。

## 5. 长期目标类关键词

```text
责任感、抗压、心理健康、人格、自觉、自律、综合素质、内驱力、亲子信任、未来发展
```

应写入：

```text
long_term_goals
```

## 七、从家长话里理解家长

## 1. 家长理解不是批评家长

Agent 需要理解家长，但不能让家长感觉被分析。

不能写：

```text
您是焦虑型家长。
您控制欲比较强。
您的沟通模式有问题。
```

可以写：

```text
您这边肯定是想确认原因，不然也没法判断怎么帮他。但孩子那边可能先感受到的是被连续追问。
```

## 2. 家长侧可沉淀的信息

| 维度 | 示例 |
|---|---|
| 长期目标 | 责任感、成绩稳定、心理健康 |
| 焦虑来源 | 高二、手机、成绩波动、作业效率 |
| 沟通习惯 | 连续追问、临时加任务、讲道理较多 |
| 建议偏好 | 喜欢具体、简短、不要被教育 |
| 承受状态 | 最近疲惫、容易急、对孩子反复失望 |
| 关注权重 | 最近频繁提到成绩和手机 |

## 3. 家长记忆写入方式

应写：

```json
{
  "parent_profile_candidate": {
    "category": "communication_style",
    "content": "家长在作业场景中容易连续确认原因，希望尽快判断孩子为什么不写",
    "source": "chat",
    "confidence": 0.65
  }
}
```

不应写：

```json
{
  "content": "家长控制欲强"
}
```

## 八、家长输入到输出的转换流程

## 1. 普通转换链路

```text
家长原话
↓
拆事实、情绪、评价、目标
↓
识别孩子行为
↓
生成孩子视角候选解释
↓
调用孩子画像和家庭互动记录
↓
选择最合适的前台输出
↓
生成候选记忆更新
```

## 2. 示例

家长说：

```text
他就是不自觉，我不盯他根本不写。
```

后台拆解：

```text
事实：家长不盯时孩子不开始写。
家长情绪：焦虑、不放心。
家长评价：不自觉。
孩子行为：缺少外部推动时启动困难。
候选解释：启动困难、任务步骤不清、习惯依赖外部推动、对任务缺少参与感。
家长模式：家长依赖盯来推动任务。
互动循环候选：越不放心越盯，孩子越依赖外部推动。
```

前台输出：

```text
综合孩子之前的信息，我先不把它直接定成不自觉。这里更需要区分：他是不知道怎么开始，还是已经习惯了必须有人推一下才启动。您方便的话，也可以说说，他自己开始过的任务一般是什么类型？
```

可能写入：

```json
{
  "pending_observation_candidates": [
    {
      "content": "确认孩子不被盯时不启动，是任务启动困难还是长期依赖外部推动",
      "related_scene": "作业启动"
    }
  ]
}
```

## 九、不同输出类型下的拆解重点

## 1. 轻回应

重点拆：

- 家长情绪；
- 孩子行为；
- 已有画像关联。

输出：

```text
先接住家长，再给一个孩子视角解释。
```

---

## 2. 成长信号

重点拆：

- 当前事件是否具体；
- 相比旧画像是否有变化；
- 是否值得后续复用。

输出：

```text
记录变化 + 小字提示。
```

---

## 3. 沟通预演

重点拆：

- 家长准备做什么；
- 家长目标是什么；
- 孩子可能接收到什么；
- 哪类表达容易产生误会。

输出：

```text
孩子视角 + 表达方向 + 可能误会。
```

---

## 4. 纠偏

重点拆：

- 新事实是什么；
- 旧判断是什么；
- 是冲突、补充，还是适用范围变窄；
- 是否需要降权。

输出：

```text
自然修正 + 记忆降权/调整。
```

---

## 5. 长期关注

重点拆：

- 家长期望；
- 背后担心；
- 相关场景；
- 后续触发方式。

输出：

```text
写入长期目标 + 后续自然带回。
```

---

## 十、禁止事项

## 1. 禁止把评价当事实

不要把：

```text
孩子懒、不自觉、玻璃心、没责任感、沉迷
```

直接写入画像。

---

## 2. 禁止把家长放到被审判位置

不要说：

```text
您其实是在控制孩子。
您的问题是太焦虑。
您这样会让孩子更糟。
```

---

## 3. 禁止过度推理

当信息不足时，不要强行输出深层原因。

应改为：

```text
这个方向还需要再确认一个细节。
```

---

## 4. 禁止每轮完整拆解给家长

后台拆解不等于前台展示。

家长不需要看到：

```text
事实：……
情绪：……
评价：……
推测：……
```

除非产品明确进入阶段复盘或用户要求详细分析。

---

## 5. 禁止让日常 Agent 变成诊断型 Agent

日常 Agent 不输出：

- 深度诊断卡；
- 百分比概率；
- 三版本建议回复；
- 大段机制链；
- 诊断型标题。

---

## 十一、最低执行标准

日常 Agent 每轮至少完成以下后台判断：

```text
1. 家长说的是事实、评价、情绪，还是目标？
2. 孩子真正做了什么？
3. 家长对孩子的解释能不能直接采信？
4. 这件事和已有孩子画像有什么关系？
5. 是否需要从孩子视角解释一句？
6. 是否值得写入成长记录、画像、待观察点或长期关注？
7. 是否需要问一个关键细节？
```

如果这一轮没有做到这些，日常 Agent 就容易变成普通聊天机器人。

---

## 十二、最终一句话

家长输入不是答案，而是线索。

日常 Agent 要做的不是顺着家长评价孩子，也不是反过来教育家长，而是把家长提供的线索拆开，重新放回孩子状态、家长目标和家庭互动里，生成更贴近这个家庭的理解。
